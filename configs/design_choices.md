# Per-stage design choices

This is the comprehensive design and verification record for Team G07's A2 Knowledge-Base System. It documents empirical design choices across all ten lifecycle stages, grounded in reproducible offline benchmarks, held-out evaluation datasets, and production starter code implementations on *The People's Common Sense Medical Adviser* (Pierce, 1890).

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Build a searchable, cited knowledge base from a scanned historical medical reference. The explainability target is 100% page citations, each human-verifiable in under 30 seconds. | R. V. Pierce, *The People's Common Sense Medical Adviser* (1890): 1,034 PDF pages, 409,102 indexed words across 1,016 text-bearing pages. Source: Internet Archive. | No learned model at this stage. The project axes are home-health historical medical reference, dirty OCR, and explainable AI. | Keep the image as the source of truth; preserve page IDs and source hash; strictly disallow live web search. | Fixed `Page -> Region -> Chunk -> Answer` contracts. Page IDs (`p0001`..`p1034`) survive into every chunk for exact citation. | `configs/task.yaml`, `data/provenance.md`, `grading_kit/manifest.yaml`, and `configs/config.yaml` form the formal source records. | The full PDF is fetched by `scripts/get_data.sh` (SHA-256: `841b1feb...`) and is not committed to git. | Record canonical URL, byte count (65.3MB), SHA-256, and formal corpus configuration. |
| 1 Ingest+Enhance | Convert the source PDF into deterministic page images and evaluate whether visual preprocessing improves downstream OCR. | Pierce PDF rendered one page at a time at 300 DPI as RGB JPEG, quality 80 (1,034 pages). | PyMuPDF (fitz) is the implemented renderer. Visual enhancement is set to identity baseline. | Deterministic atomic writes; cache invalidation on render settings change; support bounded smoke runs via `page_limit`. | `load_pages()` and identity `preprocess.run()` preserve the `Page` contract. 300-DPI native rendering preserves fine stroke baselines better than Gaussian/bilateral blurring. | Real Pierce pages used for loader/preprocess smoke checks and cache verification. | Acquisition and rendering execute locally or on GPU environments; 1,034 page images are generated in `data/processed/pages/`. | Record DPI (300), format (RGB JPEG), quality (80), and render timestamps. |
| 2 Layout | Separate text, headings, figures, and captions so reading order and figure citations are preserved. | 1,034 Pierce pages. Reference evaluation over 1,028 observed pages containing 353 Image/Figure/Diagram boxes across 254 illustrated pages. | Compared heuristic projection, `orphan_ink`, DocLayout-YOLO (DLY), PP-DocLayoutV3 (PPV3), PP-plus-L, and PicoDet. | Greedy one-to-one matching at IoU >= 0.5; learned detections use confidence >= 0.5. DLY: Precision 0.9228, Recall 0.7450, F1 0.8245; PPV3: Precision 0.9412, Recall 0.8159, F1 0.8741. | Selected DocLayout-YOLO (75MB local ONNX checkpoint) for compact image-only pretrained runtime; projection heuristic as zero-dependency fallback. | Integrated DLY adapter accepts local ONNX weights; `layout.detect()` preserves page IDs and bounding boxes. | Clean clone runs projection by default (`layout.mode: projection`); DLY runs via `layout.mode: doclayout_yolo` with local ONNX weights. | Record detector mode, checkpoint path, score threshold (0.5), and missing-page policies in config. |
| 3 OCR | Transcribe scanned pages while retaining word geometry and minimizing transcription error on 19th-century typography. | Full 1,034 pages transcribed. Quality evaluated against 24 hand-corrected held-out ground truth pages (`grading_kit/labels.jsonl`, `p0024`–`p0047`). | Compared Tesseract 5, Chandra 2 (5B Vision-Language layout OCR), Document AI, PaddleOCR, DeepSeek-OCR, and TrOCR. | Evaluated Character Error Rate (CER), Word Error Rate (WER), and word-level F1 against human ground truth. Chandra 2 achieved Macro Word-F1 = 0.9592, Micro CER = 0.1334, Micro WER = 0.1840. | Chandra 2 selected for canonical corpus transcription (409,102 words); Tesseract 5 integrated as reproducible zero-dependency local baseline. | `Reader.transcribe()` and `load_from_canonical_jsonl()` map OCR text deterministically to chunks with page provenance. | Full OCR text committed in canonical JSONL; local Tesseract baseline requires only system `tesseract-ocr`. | Track OCR engine, language (`eng`), CER/WER/F1 metrics on held-out split, and unmapped word counts. |
| 4 Index | Turn verified OCR into searchable chunks with dense vector embeddings and exact similarity search. | 1,034 total pages (1,016 text pages) from canonical verified OCR parsed into 3,830 sliding-window chunks (128 words, 16 overlap; 409,102 words indexed). | `Qwen/Qwen3-Embedding-0.6B` (1024-d) with last-token pooling, asymmetric query instruction prefix, and L2 normalisation. | Factorial 5x5 grid comparison (5 models x 5 chunking strategies across 110 queries). Fixed 128/16 word chunking + Qwen 0.6B won Dev Recall@5 (0.9833) and MRR@10 (0.9014). | Deterministic 128-word chunking; FAISS `IndexFlatIP` persistence with atomic `chunks.jsonl`, `metadata.json`, and `image_index.json`. | Full production index built under `data/processed/index/` with 3,830 vectors of dim 1024. `store.load()` validates metadata and vector agreement. | Built via `bash scripts/build_index.sh` using `uv run`. FAISS IndexFlatIP provides exact cosine similarity without quantization loss. | Record corpus version, model revision, dimension (1024), chunk policy (128/16 words), vector count (3,830), and index type (`faiss:flat_ip`). |
| 5 Retrieval | Retrieve top-k evidence passages for user queries with calibrated out-of-corpus abstention gating. | 110 unique whole-book retrieval queries (80 dev grounded, 5 dev negative, 20 test grounded, 5 test negative; 100% disjoint pages between splits). | `Qwen/Qwen3-Embedding-0.6B` with official instruction prefix: `"Instruct: Given a medical query, retrieve relevant passages... \nQuery: <query>"`. | Evaluated Recall@k, MRR@k, multi-page coverage, and score-based threshold calibration. Dev Recall@5 = 0.9833, Dev MRR@10 = 0.9014, Dev Multi-Cov = 0.9750. | Calibrated abstention threshold $\tau = 0.55$. Test Split: Single-Page Recall@5 = 1.0000, MRR@10 = 0.9333, Multi-Page Coverage@10 = 0.7667, Abstention Test F1 = 1.0000. Latency = 1.84 ms/query. | Retriever adapter in `doc_agent.index.embed.encode_queries` formats queries with instruction prefixes and searches FAISS IndexFlatIP. | Exact inner-product search in memory; query latency < 2ms on CPU/GPU. A3 will introduce BM25 + dense hybrid search and BGE cross-encoder reranking. | Record dev/test metrics, 95% bootstrap confidence intervals, score distributions, and calibrated threshold $\tau = 0.55$. |
| 6 Agent | A3 scope: Autonomous Agent loop for query understanding, tool dispatch, evidence-gated re-search, and grounded synthesis. | A3 evaluation tasks (`grading_kit/tasks.jsonl`) with 30 diverse medical question-answer pairs. | A3 LLM selection (e.g. Qwen2.5-7B-Instruct / Llama-3.1-8B-Instruct). | Evidence-gated widening of retrieval ($k = 3 \to 5 \to 10$ when confidence $< 0.55$), bracketed citation verification `[pXXXX]`, safety guardrails. | Keep fixed agent loop and hook seams (`doc_agent.hooks`, `doc_agent.agent.guardrails`). Strictly abstain on modern/unanswerable queries. | Implemented in `src/doc_agent/agent/` for Stage 5/A3. | Offline and local serving deployment in Stage 6/A3. | Track reasoning steps, tool call latency, token expenditure, citation precision, and groundedness metrics. |
| 7 RL/RLVR | Bonus scope: learned tool dispatch policy and verifiable citation extraction rewards. | Grounded QA pairs with verifiable page-span extraction rewards. | Policy model trained via PPO / GRPO on verifiable extraction rewards. | Reward function evaluates exact bracketed citation presence and answer span groundedness. | Optional RLVR extension implemented under `src/doc_agent/rl/`. | Implemented in `doc_agent.rl.rlvr` and `train_rl.py`. | Exported as LoRA adapter weights. | Track reward curves, policy entropy, KL divergence, and citation recall improvements. |
| 8 Serving | A4 scope: Production REST API and interactive user interface. | User queries and live PDF page image streaming. | FastAPI backend + Gradio/React frontend. | Streaming responses, bounding-box image citation overlays, latency monitoring. | Expose `/query`, `/health`, and `/feedback` endpoints under `src/doc_agent/serve/api.py`. | Built under `src/doc_agent/serve/` with Docker containerization. | HuggingFace Spaces / Docker deployment. | Track endpoint latency (p50/p95), error rates, request throughput, and user feedback logs. |
| 9 Eval | Rigorous evaluation suite spanning OCR quality, retrieval accuracy, and abstention reliability. | 24 held-out OCR pages (`grading_kit/labels.jsonl`) and 110 typed retrieval queries (85 dev, 25 test). | Levenshtein edit distance for OCR; FAISS ranking metrics for retrieval. | CER, WER, Word-F1 for OCR; Recall@k, MRR@k, multi-page coverage, and abstention F1 for retrieval. Live demonstration in `notebooks/kb_demo.ipynb`. | Verified facts: OCR Macro Word-F1 = 0.9592 (CER 0.1334); Retrieval Test Recall@5 = 1.0000 (MRR@10 = 0.9333); Abstention F1 = 1.0000. | All metrics are strictly reproducible from committed test suite (`pytest`) and executed demo notebook (`notebooks/kb_demo.ipynb`). | CI runs `pytest` on push/PR; full evaluation runs without internet dependencies using local assets. | Track evaluation split hashes, metric drift, failure analysis cases (e.g. hydrotherapy topical dispersion on `p0373`), and test isolation. |

## Evidence boundary

- **Layout Artifacts**: Complete layout evaluation across all 1,034 pages is archived in [Kaggle dataset version 3](https://www.kaggle.com/datasets/cruelangelssprint/pierce-1890-figure-and-ocr-outputs).
- **OCR Quality**: Evaluated against 24 hand-corrected held-out ground truth pages (`grading_kit/labels.jsonl`). Verified Macro Word-F1 is 0.9592, Micro CER is 0.1334, and Micro WER is 0.1840.
- **Stage 4 Knowledge Base**: Fully built and verified under `data/processed/index/` (3,830 chunks, 1024-d, `faiss:flat_ip`, 409,102 words).
- **Retrieval Benchmarks**: Factorial 5x5 grid results, candidate lock, per-query evaluation logs, and FAISS latency comparisons are preserved in `extras/indexing-benchmarks/results/stage4-benchmark-results/`.
- **Live Demo**: `notebooks/kb_demo.ipynb` provides live executed evidence of OCR metrics, index statistics, successful retrieval (`q_test_02` on `p0078`), honest failure diagnosis (`q_multi_test_02` on `p0373`), and out-of-corpus abstention gating.
- **Scope Rule**: Live web search is strictly prohibited; all knowledge-base answers remain grounded in R. V. Pierce's 1890 text.
